## dev.3 UI clock scripting name

The musician reports that dev.2 opens the editor and the Set is now fluid. A read-only screenshot through Live confirmed the editor displays the expected configurations and the warning `Cannot read properties of null (reading 'message')`. This is musician feedback about responsiveness, not an instrumented Live performance measurement or confirmation of the pending ALS save/reopen test.

The editor's `qmetro 100` had JSON box ID `layoutclock` but no Max scripting name (`varname`). `KLJView.setVisible` calls `getnamed("layoutclock").message(...)`; the failed lookup interrupted clock/mouse startup on open and cleanup on close. The view became visible before that exception, and the error handler rendered its data, explaining the apparently usable window with a warning. dev.3 adds only the missing scripting name to the runtime patch, along with its version label. All four runtime JavaScript files, the persistence parameter and data schema remain byte-identical to dev.2.

The simulated host now returns null for names absent from the actual patch's scripting names, instead of inventing arbitrary named objects. A new regression test reproduced the exact reported warning on the old patch and passes on dev.3; it verifies UI clocks start/stop without data persistence or Live writes. **58 Node tests pass**. The native-container validator now checks literal UI `getnamed` references against the editor's scripting names. Source/binary and six-file packaging checks pass. Integrated Max accessibility still times out, so native dev.3 execution is not claimed. The dev.3 files are staged separately on the Desktop; the running installation and ALS are unchanged.

## dev.2 editor-opening correction

The musician confirmed dev.1 loaded in the existing test Set, but OPEN CONFIGURATIONS did not open its window. Inspection found a patch-routing defect: the added `t b b` sent a bang directly to `pcontrol`, losing the original `open` selector. dev.2 inserts an explicit `open` message before `pcontrol`, retaining the editor-open notification order. The validator now checks this message and its connections in both source and generated AMXD. No musical JavaScript or persistence changes were made for this correction.

The 57 Node tests, native-container validator and six-file packaging checks pass for dev.2. The new ZIP was extracted to the Desktop test staging folder; the running installation and test ALS were not overwritten. A native UI attempt reached Live, but launching integrated Max returned `procNotFound`; actual dev.2 editor opening is therefore not claimed and needs the musician's retry. This does not validate ALS save/reopen or performance in Live.

## Implemented

- Removed the recurring 2-second full-track scan. Track structure and eligible MIDI names invalidate an inventory cache; notifications are grouped into a 50 ms task. Existing name observers are retained by Live identity rather than recreated on every inventory. Device-chain scans/observers are not needed to include all normal MIDI tracks.
- Clip callbacks use their own immediate task, not the structural scan task. They retain the existing Gate, real-playing confirmation, stop handling and pre-apply snapshot. A 100 ms retry exists only while a clip identity is pending but not yet playing; it cancels on playback/stop. There is no stable-playback polling timer.
- Recall scans only if the inventory was invalidated. The original `guardedTrack`, `setIfDifferent` and `snapshot` functions are byte-identical to v1.5.1. This deliberately leaves the expensive per-target guard work for a later phase.
- Closed editor stores a dirty view and defers matrix/highlight/layout work. Mouse polling and the layout qmetro start only when opened, and stop on the native editor closebang. Opening refreshes tracks and renders the latest state. Compact diagnostics can still update when a real event needs attention.
- Added REFRESH TRACKS without recalling configurations, resetting the Gate or replaying scripts. Selecting an already-selected menu value or merely toggling details no longer invokes the model-change persistence path unnecessarily. Full incremental rendering is not implemented.

## Configuration safety

The patch keeps the exact `state` object declaration, `pattr klj_state`, parameter declaration (`KLJ Configurations`, Blob / Stored Only), schema version 1 and adjacent JS paths. The runner is unchanged. No external backup format or complex schema migration is introduced.

The engine waits for an explicit pattr response and never auto-writes an empty default during loading. Invalid/partial/unsupported restores retain their raw payload and lock writes, edits and recall. A default scalar cannot clear this lock. An inventory is reconciled on a candidate copy before commit. Previously unresolved references are retained across reopening/refresh rather than deleted; extra legacy track/row/root metadata survives. Existing confirmed-deletion behavior remains for tracks actually identified and deleted during the session.

See [data policy](../docs/DATA_COMPATIBILITY.md) and [update instructions](../INSTALLATION.md#updating-from-a-previous-version). Retaining parameter metadata is structural evidence, not proof that a particular Live/Max version restores an instance correctly.

## Real Live validation — NOT completed

Live was reached through the native UI, an existing audio-output-disabled notification was acknowledged without changing audio settings, and a private copy of an existing configured Set was prepared. Its AMXD references were redirected to a separate installation containing the exact v1.5.1 runtime. The original Set and its installation were not changed.

The copy was selected in Live's Open dialog. Subsequent accessibility and screenshot requests timed out during loading. Consequently no successful baseline load, candidate upgrade, UI inspection, ALS save/reopen, native Phase 1 execution, hardware test or Live performance improvement is claimed. The private copy contains user data and remains outside Git. No save of the original Set was attempted. A musician test has been requested using the concrete development ZIP and LIVE_TESTS.md.

This is a **test candidate**, not a demonstrated safe production upgrade. Release remains blocked pending a successful in-place update and save/reopen in the real Set, comparison of all configuration fields, and the performance/music checklist. The public v1.5.1 Release remains untouched.
